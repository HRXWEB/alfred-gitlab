把 AI 用在漏洞分诊与修复

区分 SAST 误报分析、漏洞修复、密钥误报和 MR 安全审查，按正确入口使用。

从一个真实工作问题开始

默认分支扫描发现很多 High / Critical 漏洞。你希望先确认哪些值得处理，再对明确问题生成修复 MR。AI 能协助分诊与实施，但扫描报告、判断和最终修复是三个不同阶段。

01 · 先有有效扫描，再用 AI

需要相应安全功能授权，通常是 Ultimate / 旗舰版，以及 Agent Platform、对应内置流程、Runner 与服务账号条件。项目必须先运行受支持的 SAST 或 Secret Detection，产生有效发现。仅升级到 19.3.3 不会自动给旧仓库补出完整漏洞报告。

02 · SAST 误报分析：解释为什么可能不成立

  1. 默认分支的 SAST 成功后，满足条件的 High / Critical 发现可以被自动分析。
  2. 手动处理时进入 Secure → Vulnerability report，选择一个具体漏洞。
  3. 点击 AI actions → Check for false positive。
  4. 检查解释、置信信息和实际代码路径。高置信度也不是自动忽略漏洞的充分理由；由安全维护者决定是否调整状态。

操作依据：SAST 误报分析入口与自动条件 · 固定 19.3.3 文档 ↗

03 · SAST 漏洞修复：生成可评审变更

  1. 启用 Resolve SAST Vulnerability，先检查漏洞详情中的证据与所在代码。
  2. 对支持的发现，在漏洞页面选择 Resolve with Agentic AI，或者使用已配置的自动分析路径。
  3. 到 Session 与关联 MR 查看修复。核对它是否消除了真实数据流风险，而不是仅压制扫描规则。
  4. 重新执行扫描与相关功能测试，安全维护者验收后再合并。
不要提及一个漏洞修复服务账号来尝试触发这类安全流程有专用入口或扫描后的自动条件。固定版本文档明确说明，提及、指派或请求 review 不是 SAST 漏洞修复 / 误报分析的触发方式。

操作依据：漏洞修复的专用入口与执行条件 · 固定 19.3.3 文档 ↗

04 · 19.3 新增的批量执行怎么用

  1. 进入 Secure → Vulnerability report，先按严重程度、分析器或项目范围筛选，避免把不适用的发现混在一起。
  2. 勾选多条要处理的 SAST 漏洞，使用报告提供的批量 AI 操作，选择误报分析或漏洞修复。实际中文操作名称以 JH 界面为准。
  3. 分别检查每条任务的结果和生成 MR，不把“已发起”当作“全部修复成功”。
  4. 先用少量已理解的发现确认权限、执行与用量，再扩大处理规模。

操作依据：19.3 批量执行 SAST 分析与修复 · 固定 19.3.3 文档 ↗

05 · 密钥误报分析：评估发现，不等于密钥轮换

默认分支完成 Secret Detection 后可分析发现；手动入口同样是漏洞详情中的 AI actions → Check for false positive。它帮助解释某个字符串是否可能为真实密钥，不负责自动撤销、轮换或恢复泄露凭据。

  1. 检查发现的文件、提交历史与字符串用途。
  2. 运行误报分析，阅读解释，并结合密钥提供方信息判断。
  3. 如果确实泄露，按凭据管理流程处理；删除代码里的字符串不能撤销已泄露的密钥。

操作依据：Secret false positive detection · 固定 19.3.3 文档 ↗

06 · MR Security Review 与普通 Code Review

普通代码评审关注潜在错误与项目标准，Security Review Flow 重点分析变更中的安全问题。不要将其与 SAST 漏洞修复混为一谈：一个分析 MR，另一个从扫描发现出发生成修复。

Security Review 在上游 19.3 为 Ultimate / Beta；先启用对应流程，并确认 striding 提供它。

  1. 打开 MR，在右侧 Reviewers → Edit 中搜索 Duo Security Review，选择当前顶层群组的服务账号。
  2. 等待完成后检查内部说明与相关行上的 diff 线程；公共项目的结果只放在内部说明中。
  3. 在讨论中提及实际的 @duo-security-review-… 账号追问证据。仅提及是追问，不会重新执行完整 review。
  4. 应用修复后，重新指派该账号作为 reviewer 才会按更新后的 diff 再审查。

这项流程不会因为“没有发现问题”就给出 Approve，其发现也不会自动进入 Vulnerability Report 或审批策略计数。把它作为补充审查，并保留人工判断。

操作依据：Security Review Flow 专项参考 · 固定 19.3.3 文档 ↗

07 · 怎么证明安全工作有所推进

记录：哪些发现被确认、哪些被判为误报、哪些生成 MR、哪些重新扫描后消失。AI 评论数量不能代表修复质量。即使扫描消失，仍要验证修改没有破坏原有权限、输入校验与业务行为。
