把重复协作做成 Agent 和任务流

从一个团队场景出发，用 Flow Creator 生成配置，再注册、启用和测试。

Flow Creator 为 19.3 新增Custom agents / flows

从一个真实工作问题开始

每次新 MR 都要查 Issue、整理验收条件、检查测试说明，然后发出一条结构一致的评审准备评论。这个任务有重复步骤和明确产物，适合形成可复用流程，而不是每次重写长提示词。

01 · Agent、Flow、Catalog 分别负责什么

概念主要作用适合什么
Custom agent系统提示词 + 可用工具，供聊天调用一个懂团队约定的问答或分析助手。
Custom flow通过 YAML 定义多步骤、输入、路由和交互事件触发、需要顺序与结果衔接的重复任务。
AI Catalog创建、管理、发现并在项目中启用能力组织内复用，并管理可见性和版本。
Flow Creator帮助生成和调试 Flow Registry v1 YAML 的内置 Agent把自然语言需求转为可校验的流程定义。
不是把聊天 Agent 名字连起来就能成为 Flow19.3.3 文档说明：自定义 Flow 根据自身 YAML 创建和使用 Agent，不能直接把 AI Catalog 中一个特定 custom agent 当作可任意调用的节点。应按 Flow Registry 的组件与 schema 构建。

02 · 用 Flow Creator 把需求说清楚

  1. 启用 foundational agents，并进入目标项目或群组。
  2. 在 Duo 侧栏点击 Add new chat，从下拉菜单选择 Flow Creator。
  3. 说明触发事件、输入、预期产物、允许调用的资源与需要人确认的位置。重点描述结果，不要先猜 YAML 组件名。
  4. 检查生成的 YAML。如果校验失败，把完整 YAML 和具体错误一起交回 Creator 调试。
Flow Creator 提示词 · 小范围演示
创建一个 Flow Registry v1 任务流：
在测试项目中通过 Mention 手动触发。
读取指定 MR 的描述和关联 Issue，整理验收条件、测试说明和待确认项。
只生成一条待发布评论草稿，不修改仓库文件、不合并 MR。
发表评论之前加入人工检查点；人拒绝时停止执行。
请列出需要的输入、工具、触发器和校验方法。

Creator 会读取框架文档，所以首次回复可能较慢；它生成配置并不意味着配置已经注册或启动。它只生成 Flow Registry v1 schema。

03 · 注册、启用，然后触发

  1. 具备 Maintainer 或 Owner 角色的维护者进入 AI → Flows → New flow。
  2. 填写名称和说明，选择 managing project 与可见性。在 Configuration 中选择 Flow，粘贴 Creator 输出的完整 YAML，完成校验后创建。
  3. 到 AI → Flows → Managed 打开刚创建的流程，点击 Enable。
  4. 选择测试项目，在 Add triggers 配置 Mention 等实际事件，再确认 Enable。创建配置和启用触发是两个步骤。
  5. 查看新生成的服务账号，使用真实用户名在测试 MR 上提及，按配置提供输入。到 AI → Sessions 检查每步执行。

若提示缺少工具或输入，不要猜一个字段继续尝试。把校验错误反馈给 Creator，并以该实例支持的 schema 为准。

操作依据：创建、启用、触发与服务账号 · 固定 19.3.3 文档 ↗

04 · 只需要专用聊天助手：创建 custom agent

  1. 进入 AI → Agents → New agent，填写名称、描述和可见性。
  2. 在 System prompt 定义职责与输出格式；在 Available tools 只选择任务需要的工具。
  3. 创建后到 Managed 列表打开并 Enable 到项目；创建成功不代表聊天里立刻可选。
  4. 在 Duo 的新聊天下拉菜单中选择该 Agent，用同一组测试问题验证它的输出。
System prompt 示例 · 仍需配置实际工具权限
你是团队的 MR 准备助手。
先读取指定 MR 与关联 Issue，整理目标、验收条件、测试证据和待确认点。
每条结论引用实际资源；拿不到的上下文明确写“未取得”。
默认只分析，不创建 Issue、提交或评论。
对用户要求的写入操作，先说明准备产生的具体结果。

系统提示词不是权限隔离。若不希望它写数据，应在工具选择与执行权限中体现，而不只写“默认只读”。

05 · 团队复用与验收

19.3 新增 Restricted 可见性，可在同一顶层群组内复用；Private 限于管理项目，Public 对实例用户可见。这个设置控制 Agent / Flow 配置的可见性，不自动授予其读取所有项目数据的权限。

  1. 先使用 Private 范围测试成功和失败输入。
  2. 验证触发只发生一次，不因它自己的评论反复触发。
  3. 在写评论前检查草稿，故意拒绝一次以确认停止行为。
  4. 需要跨项目复用时再选 Restricted，并在第二个项目确认授权与触发条件。
