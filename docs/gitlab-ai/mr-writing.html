减少 MR 描述、评审摘要和提交信息的重复写作

这些生成式功能在 19.3 之前已存在，入口与授权与 Agentic 编码流程并不完全相同。

Duo Enterprise 等授权需确认Summary 含 Beta / Experiment

从一个真实工作问题开始

代码已经完成，MR 却只有一句“fix bug”。你希望 AI 先整理行为变化和评审意见，再由自己补齐测试证据与迁移影响。生成摘要可以节省写作，但不能替你证明代码正确。

01 · 从代码差异生成 MR 描述

  1. 确认实例支持该功能并为用户分配相应 Duo Enterprise 使用权；固定 19.3.3 文档将 MR Summary 标为 Beta。
  2. 新建或编辑 MR，在 Description 中把光标放到希望插入的位置。
  3. 点击编辑器上方工具栏的 Summarize code changes。
  4. 检查生成文字，再补入问题背景、用户可见行为、真实测试结果与已知限制。
MR 描述示例 · 不把摘要当成验证结果
背景：默认分支不是 main 的项目无法从 Graph 快捷入口打开。
行为：改为使用 HEAD 引用。
验证：已执行的测试与结果填写在这里。
限制：未对 striding 私有实例完成真实页面联调。

操作依据：MR Summary 入口与授权 · 固定 19.3.3 文档 ↗

02 · 提交评审前，整理评论摘要

Code Review Summary 在固定版本中为 Experiment，需要对应 Duo Enterprise 授权。它总结你已经写好的 review 评论，不等于让 AI 再做一次完整 review。

  1. 先完成逐行评审并保留准确评论。
  2. 准备提交时点击 Finish review。
  3. 选择 Add Summary，检查插入到评论框的摘要。
  4. 删除过度推断，补上阻塞项与可选建议的区别，再提交评审。

操作依据：Code Review Summary 操作 · 固定 19.3.3 文档 ↗

03 · 合并时生成 commit message

  1. 在 MR 的合并区域选择 Edit commit message。
  2. 点击 Generate commit message。
  3. 检查内容、Issue 引用和项目提交格式，选择 Insert。
  4. 按项目要求保留清楚的变更原因；生成消息本身不会替代 MR 审批或合并规则。

操作依据：生成 merge commit message · 固定 19.3.3 文档 ↗

04 · 什么时候改用 Agentic Chat

若专用摘要入口没有授权，不能据此认定整个 Agent Platform 不可用。可以在已授权的 Chat 中请求整理指定 MR 上下文，但得到的是聊天输出，不是已自动写入 Description 的结果。无论使用哪条路线，都要自己确认测试、部署影响与未验证事项。
