把一个 Issue 交给 Developer Flow

写清验收条件，用指派或提及触发，让平台在 Runner 中实施并生成待评审结果。

18.8 已 GA平台 / Runner 执行

从一个真实工作问题开始

待办中有一项很具体的需求：给项目列表请求增加分页。你希望把机械实现委派出去，自己把时间花在边界条件和评审上。Developer Flow 的输入应是一份可以交给同事执行的任务。

01 · 准备好仓库，再交任务

先完成 实例与执行环境准备。用户需具备 Developer、Maintainer 或 Owner 角色，启用 Developer 内置流程；服务账号应能创建提交和分支。不要把“有一个在线 Runner”与“Agent 的执行环境已可用”混为一谈。

Markdown · 根据本仓库约定调整
# AGENTS.md
## 项目约定
- 保持 Python 3.9 兼容。
- host 之间的缓存与凭据必须隔离。
- 网络刷新失败时保留旧缓存。
## 验证
- 先安装项目所需测试依赖。
- 运行 python -m pytest -q。
- 如需构建 workflow，先按 README 暂存源文件再构建。
- 报告实际执行的命令；不能运行时说明阻塞。

AGENTS.md 提供上下文，不是执行环境。依赖和镜像应配置在默认分支的 .gitlab/duo/agent-config.yml 中。不要因为写了“运行测试”就假定它拥有所需依赖。

操作依据：Developer Flow 前置条件与仓库准备 · 固定 19.3.3 文档 ↗

02 · 把 Issue 写到“能验收”的程度

Issue 模板 · 示例任务
标题：为 GET /projects 客户端补充分页

现象：拥有超过一页项目时，后续项目没有进入缓存。
范围：只修改项目列表请求与相关测试，不更改 host 配置。

验收条件：
1. 按 X-Next-Page 获取所有页面，终止时不继续请求。
2. 任何一页失败都不能发布半份新缓存。
3. 保留项目 Web、SSH 和 HTTP 克隆地址。
4. 已有测试通过，并覆盖至少两页数据与第二页失败。

交付：先提交实施计划，再生成草稿 MR，附测试结果。

文件路径、失败日志、接口约定和 Issue 链接越具体，Agent 越容易正确定位。不要在同一个任务中同时要求分页、缓存重构、UI 改版和迁移依赖。

03 · 在网页中发起任务

  1. 进入 Plan → Work items，筛选 Issue 并打开任务。
  2. 可以在 Assignees 中搜索 duo developer 并指派对应服务账号；也可使用 Issue 标题下的 Implement work item。
  3. 如果项目已配置 Mention 触发器，也可在评论中提及该群组实际的 Developer 服务账号，说明要做什么。
  4. 到 AI → Sessions 查看执行；完成后回到 Issue 的 Activity 中打开 MR 链接。
评论示例 · 替换成实例中真实服务账号
@duo-developer-<namespace> 请按本 Issue 的验收条件实施。
先检查现有缓存失败处理逻辑，再创建草稿 MR。
不要扩大到其他模块，并在 MR 中说明实际测试结果。

服务账号用户名来自实际配置。不要原样提交 <namespace> 占位符。如果 Mention / Assign 事件没有配置，评论本身不会自动开始任务。

操作依据：指派、提及和 Implement work item 入口 · 固定 19.3.3 文档 ↗

04 · 在同一个 MR 上继续迭代

打开结果 MR，先看 diff，再看测试。明确的补充意见可继续提及 Developer 服务账号：

评审反馈 · 指定问题与验收方式
@duo-developer-<namespace> 第二页失败时仍然发布了部分缓存。
请修改为所有页面成功后再发布，并补充回归测试。
保留已经完成的其他改动。

如果要处理一个特定评审线程，19.3 还有更直接的 Resolve with GitLab Duo 入口。若只是想调研方案，应明确要求“只回复调研结果，不修改代码”。

05 · 结果验收与常见阻塞

检查点通过标准
问题是否解决把 Issue 每条验收条件映射到代码与验证。
测试是否可信查看 Session / CI 的真实输出；“应该通过”不算通过。
权限是否正确修改仅发生在预期分支，没有为了提交而绕过分支规则。
MR 是否便于审查有范围、行为变化、验证结果和限制。
Session 失败时先找具体阻塞排队看 Runner，拉镜像失败看网络与仓库权限，提交失败看服务账号与 push rules，测试失败看环境和命令。换一个更长的提示词通常无法解决这些基础问题。
