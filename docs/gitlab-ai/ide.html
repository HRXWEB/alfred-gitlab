02 · 小片段编码：Code Suggestions

  1. 在 VS Code 或 JetBrains 安装并配置官方 GitLab 扩展，连接 striding 的实例 URL 并完成认证。打开有 Duo 权限的项目，检查默认 namespace。
  2. 打开源文件，输入代码或描述需求的注释。生成的建议会显示在光标附近。
  3. 完整接受用 Tab；拒绝用 Esc；也可继续输入忽略建议。部分接受的快捷键按 IDE 对应设置操作。
  4. 检查空值、边界、异常路径和现有风格，再把生成代码纳入实际测试。

03 · 跨文件理解：Agentic Chat

  1. VS Code 中启用 GitLab › Duo Agent Platform: Enabled，在左侧打开 GitLab Duo Agent Platform → Chat。JetBrains 使用 GitLab Duo 插件的 Agent Platform 聊天入口。
  2. 网页端进入目标项目，在右侧 Duo 栏选择 Add new chat，选择可用 Agent，并确认 Agentic 开关。
  3. 先说明“只分析、不改文件”，给出错误现象和相关 Issue / MR 地址，要求引用文件和函数。
  4. 检查它是否真的读取到了相关文件，再允许实施。涉及终端或文件操作时，按工具权限提示检查具体动作。

IDE Chat 可访问本地项目文件；网页 Chat 面向 GitLab 上的仓库与协作资源。不要假设网页 Agent 能看到你尚未提交的本地改动。Agentic Chat 可以执行操作，普通问答的语气不代表它一定处于只读模式。

04 · 需要一整次开发任务：Software Development Flow

  1. 在 IDE 中选择 GitLab Duo Agent Platform → Flows，在文本框中填写详细编码任务。
  2. 描述目标、允许修改的范围、兼容要求和验收命令，关联必要的 Issue / MR 上下文，然后点击 Start。该流程可以暂停或要求调整计划。
  3. 观察生成的计划与实际文件修改。若计划偏离任务，及时补充约束，不要等它完成无关重构。
  4. 完成后检查本地 diff、测试输出与未完成事项，再决定提交哪些变更。
提示词 · 交付可复核的变更
修复 GitLab 项目分页刷新。
保持 Python 3.9 兼容，不改变多 host 缓存隔离逻辑。
先阅读 update.py 和相关测试，复用现有测试方式。
覆盖两页数据和第二页失败场景，执行实际可运行的测试。
结束时列出修改文件、测试命令、结果和未验证事项。

固定版本的软件开发流程不访问外部网站。需要的设计说明或线上文档应作为可用上下文提供；不要要求它在没有浏览能力时“自己上网查齐”。

05 · 19.3 的新聊天界面改变了什么

19.3 引入的新版 Agentic Chat UI 是 Beta，适用于 GitLab for VS Code ≥ 6.88.1、JetBrains GitLab Duo ≥ 3.45.2。需要在顶层群组或实例启用 Beta / 实验功能后重新加载扩展。它改变交互界面，不表示模型、工具或每项 Agent 能力也在 19.3 首次出现。

没有新版 UI 不等于无法使用 Agent先检查经典界面中的 Chat / Flows。真正的阻塞通常是授权、认证、命名空间或 Agent Platform 开关；不应仅因为界面与截图不同就重装整个 workflow。

操作依据：19.3 发布说明（新 IDE UI） · 固定 19.3.3 文档 ↗

06 · 怎么判断它做对了

先对照任务检查“改动是否最小”，再核对测试命令是否真的运行。要求它解释缓存失败、空结果和多 host 并发这些边界。对于编译失败或测试未运行的结果，先补齐环境和证据，再提交 MR。

  • 问答正确：能引用真实代码，不把计划中的行为写成现有行为。
  • 生成可用：保留接口与兼容要求，没有用大重构掩盖小修复。
  • 结果可复现：你在相同目录与环境中可以重跑所列测试。
