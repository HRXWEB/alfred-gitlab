从一个真实工作问题开始

你已经登录新版 striding，却看不到 AI 按钮。此时先分清：你要的是编辑器补全、MCP 接入，还是在服务器上跑任务流？三者的前置条件并不相同。

01 · 先选任务发生在哪里

工作方式执行与产出首先读哪一章
IDE 中问答、改代码本机工作区；开发者检查 diff 后提交代码补全与 Agentic Chat
已有 coding agent 连接 GitLab外部客户端调用 GitLab MCP；模型由客户端提供MCP 接入
Issue 交给平台实现Runner 中执行；产出 MR 和会话记录Developer Flow
Duo 在终端协作本机或指定自动化环境；使用 GitLab 的 Agent PlatformDuo CLI

02 · 管理员：确认“发行版、授权、模型”三件事

19.3.3-jh 标识极狐发行版，不表示专业版、旗舰版或 Duo 订阅已开通。先在实例管理界面核对版本和许可证，再向管理员确认目标功能的使用权。不要把 JihuLab.com 基础版可购买 Credits 的规则直接套到私有化实例。

检查项要得到的具体答案
发行版与版本实例实际是否为 19.3.3 JH；是否有厂商或公司自定义补丁。
授权与计费Duo / Agent Platform 的授权方式、可用用户、Credits 或自部署模型授权。
模型服务使用极狐托管、云连接还是自部署网关；实例到模型服务能否连通。
目标范围在哪个顶层群组和测试项目启用；谁具有 Developer 以上角色。
JH 与上游的边界下文的固定版本操作以 GitLab 19.3.3 官方源码文档为依据，极狐可能使用不同模型、中文菜单与授权方案。功能是否已在 striding 开通，要用实际许可证、管理界面和一次任务结果确认。

操作依据：Agent Platform 开关与自部署授权条件 · 固定 19.3.3 文档 ↗

03 · 从实例到项目逐层开启

  1. 管理员进入 Admin → GitLab Duo → Change configuration，检查 Duo availability 与 Agent Platform。需要平台能力时勾选 Turn on GitLab Duo Agentic Chat, agents, and flows。
  2. 根据目标功能开启相关能力：例如内置任务流的 Allow flow execution → Allow foundational flows → Developer / Code Review / Fix CI/CD Pipeline。只开启 Agent Platform 总开关还不够。
  3. 群组维护者在 Settings → General → GitLab Duo features 检查群组与子群组设置；项目维护者在 Settings → General → GitLab Duo 检查项目设置。
  4. 需要实验或 Beta 功能时，另行检查 beta and experimental features。Always on 不会自动开启 Beta。MCP 在 19.3 仍要检查这一项。
  5. 多群组用户在个人 Preferences 中设定默认 GitLab Duo namespace，避免 IDE 或聊天选错授权归属。

操作依据：内置任务流的实例、群组和项目开关 · 固定 19.3.3 文档 ↗

04 · 跑在 Runner 上的能力，还需要执行环境

网页中的 Developer、Code Review 和 Fix CI/CD Pipeline 会使用 CI 执行环境。管理员或维护者要准备支持容器镜像的 Runner，并按固定版本要求配置 gitlab--duo 标签。服务账号还要能创建分支、提交并通过项目 push rules。

  1. 准备一个可用的、支持 Docker 镜像的 Runner，确认它能接到带 gitlab--duo 标签的任务。Shell executor 不能简单代替镜像执行环境。
  2. 确认 Runner 能拉取 Agent 镜像，能访问 GitLab、AI 网关和测试所需依赖源。私有镜像仓库需要单独配置访问。
  3. 把执行环境文件合并到默认分支。放在 feature 分支上不会生效。
  4. 在测试 Issue 上触发一次 Developer Flow，检查 Session 是否启动、CI 作业是否执行、是否产生可审查结果。
YAML · 项目执行环境示例
# .gitlab/duo/agent-config.yml
# 演示一个仅依赖 pytest 的 Python 项目；按实际工具链调整。
image: python:3.11
setup_script:
  - python -m pip install pytest

这个文件负责准备环境，不会自动替你定义完整验收流程。把正确测试命令写入项目 AGENTS.md，并在任务中要求报告实际执行结果。setup_script 应由维护者审查，因为它在任务启动前执行。

05 · “没有按钮”和“任务失败”分别排查

现象先检查什么下一步
整个平台没有 AI 菜单授权、Duo 可用性、Agent Platform 总开关让管理员确认；反复换 PAT 不会补齐许可证。
有 Chat，没有 Implement / Review对应内置流程开关、角色、命名空间在测试项目逐项开启目标流程。
Session 出现但一直排队Runner 标签、executor、Runner 在线情况查看任务是否被 Runner 接走。
任务启动但无法提交服务账号、push rules、分支保护保留日志中的拒绝原因，按项目规则修复。
能改代码却不能运行测试镜像、依赖、工作目录、测试命令配置环境后重新运行小任务，不接受虚构的通过结果。
